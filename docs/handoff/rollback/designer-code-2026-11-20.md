## LIMITS

**The API returns more than API-registered scripts. It also returns the code pasted into the Designer's custom code fields.** `data_scripts_tool` has two separate kinds of read:

- **API-registered scripts:** `get_registered_scripts`, `get_registered_script`, `get_site_scripts` and `get_page_scripts`. These show only scripts registered through the API. On this site that is one: `ga4_phone_email_click_tracking`, applied site-wide in the footer and applied to no page.
- **Code pasted in the Designer:** `get_site_freeform_code` and `get_page_freeform_code`. These returned the Site settings head and footer code and each page's settings head and footer code. The content is the hand-written code (Lenis, the CodeSandbox `homewrap-main.js` loader, UTM/attribution scripts, JSON-LD, the cursor script on Home and Portfolio, the Ads conversion snippet on Thank You). So these reads do return code pasted in the Designer.

This audit cannot see:
- Code Embed elements placed on the canvas. They are page elements, not custom code fields.
- Code added by Webflow's built-in integrations, such as the Google Analytics or Google Ads ID in Site settings. No `gtag` base tag appears in any code read, but the Thank You snippet calls `gtag`.
- Utility pages (404 and password) and folders, because `list_pages` doesn't return them.
- Secondary locales, because only the primary locale was read.

As the Project facts already say, the head code has no wf-template loader. The bundle still loads from `8n3dq9.csb.app` in the site footer (tracker HW-01).

I couldn't call `webflow_guide_tool` because permission wasn't granted. I skipped it, and that changed nothing in these reads.
